## Current UX

Changes has two compact rows opening normal workspace tabs. Inbox links choose the related conversation explicitly. The views reuse theme tokens, small text controls, native disclosures, existing diff/markdown rendering and the existing agent context picker. Pipeline setup reuses the Settings Popover dropdown. Provider/account/revision details are expandable; PR status/comments and pipeline run lists load on opening. The first pipeline also opens its matching run/jobs; other details and logs load on selection. No new UI library, dashboard or polling was added.

This review fixed full CI Refresh destroying the selected run/job/log, preserved a still-valid repository choice, and cleared CI evidence on a confirmed account change. Account/checkout checks gate actions while refreshing. Missing job logs now say “No log available”; source errors offer Connection settings. The PR repair button explicitly labels its first-20 limit when applicable, and each unresolved thread can be repaired individually, including threads beyond that limit. The repair sheet now offers a real Refresh evidence action that returns to the retained PR/CI tab and initiates fresh reads, without dispatching a repair. Edited instructions carry into the next draft for the same artifact. Saved sidebar summaries expose review attention and the selected CI commit.

## Local recovery follow-up

- Delivery tabs use React Activity to preserve component/DOM state while suspending hidden effects, including when their whole workspace or Inbox replaces the view. Generation checks discard reads started before a hide/reopen; returning account/head checks still invalidate inappropriate evidence. Loaded state lasts while the workspace tab remains open; closing the tab or restarting restores saved associations, not log bodies.
- The React and React type minimums are now 19.2 to match this API. Resolved lockfile versions were already compatible and did not change; no new dependency or persistence schema was introduced.
- Link a PR now uses the same inline bordered form, padding, typography and action layout as Connect pipeline. Cancel clears lookup results but retains typed link/branch values. Story/branch discovery and multiple PR association remain intact.
- New regressions cover PR/CI tab-return identity and scroll (CI exercises the actual FilePane visibility boundary), no hidden event-triggered reads, late thread responses after hide/reopen, actual refresh callbacks, retained repair instructions, and cancel/reopen of the PR form.
- In the disposable browser fixture, the actual FilePane/SurfaceTabs/PR/CI components retained a scrolled CI log and expanded PR thread across switches. Fix CI → simulated stale dispatch → Refresh evidence returned to the existing CI view with focus restored to Fix CI. Recovery explicitly reveals the owning pane/file/workspace if a fresh-session attempt moved focus elsewhere; hidden PR recovery waits for activation before reading. The inline PR form was visually compared with the pipeline form. Provider IO and dispatch were mocked; no live agent message was sent.
- Fresh independent review identified that revealing another workspace must use the existing tab activation path to synchronize project CWD/recents as well as the selected tab. This was corrected by reusing `activateTab`; no replacement navigation helper was introduced. The review also corrected one false positive after checking keyed file/iteration/revision remounts. Representative native performance and live provider/platform acceptance remain unverified.

## Comment picker and automatic preparation follow-up

The repair sheet now lists individual comments with author, short body and optional file/line, using the same ContextCheckbox as Inbox and Changes. Each comment can be selected separately, including replies in one thread. Instructions remain editable; destination and checkout metadata use compact disclosures. A prepared repair checkout cannot be accidentally replaced with an unrelated project in the picker. Native macOS accessibility interaction verified individual deselection, selected count and disabled submission at zero comments. No repair was dispatched during verification.

PR opening refreshes status and comments automatically. Preparation reuses a matching checkout or creates an isolated authenticated checkout under application data, then verifies repository, branch and PR head again. Existing user working copies are preserved. Cancel preparation and hidden-view cancellation stop Git work; failed final verification removes only the new unpublished checkout. Automatic cloning currently supports native host, non-fork PRs; existing matching WSL checkouts can be reused, but automatic WSL cloning remains unsupported.

Inbox PR and CI shortcuts have independent provider choices per ticket/conversation. GitHub and Azure tickets default to their provider; Jira requires a visible choice. Mixed overrides can be reset to the ticket default. GitHub shortcuts use the existing external PR/checks pages; Azure opens its native panel.
